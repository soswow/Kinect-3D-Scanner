# Combined ICP source guard causal experiment

This is a separate component experiment. It preserves the eight previously
measured combined audit/timing sources, the original nine fragment proposals,
their ordering, every native bridge gate and all resident numerical kernels.
It creates no whole-Finish or production registration authority.

The completed stdlib microbenchmark in
`benchmark-output/field-cuda-study/combined-sync-source-guard-v1/source-check.json`
measured 236 checks per round with three alternating rounds. Full original AST
source-contract reconstruction took a median 1.8644914 seconds; exact whole-file
SHA checks took 0.0203218 seconds. These isolated primitive measurements justify
a causal component test; they do not establish a registration speed gain.

The new sibling constructs and checks the complete original source contract
once. Its `whole-file-sha` call guard then checks the exact complete original
source bytes, unchanged cached contract, generator policy and function ownership,
immutable code/default/keyword-default/closure state, and the inherited actual
configuration. It preserves the original per-iteration configuration guard.
The `original-ast` control retains repeated original source reconstruction.
Both modes add identical nested source-check and preenqueue host clocks.

The fresh registry-owned authority composes the original timing authority with
five new current source pins. It validates the original synthetic and all-nine
Device and combined proofs against the installed runtime, configuration, raw
fixture, target membership and original math. An equal manufactured token cannot
activate the adapter. Inverse AST checks recover every original iteration and
bridge statement after removing only clock statements and constructor import
injection. CPU resolution of ambiguous queries still precedes original equations;
malformed/device/unsupported complete calls stop with the inherited hard fault.

After an explicitly allocated hardware slot, run these commands separately with
fresh output paths. Each runs three rotating contemporary native, original
Device and sibling combined rounds; it checks all nine proposal results and
original witness, pose, information, decision and support evidence.

```powershell
python scripts/research/benchmark_combined_source_guard_timing.py --run-allocated --source-check-mode original-ast --output benchmark-output/field-cuda-study/combined-sync-source-guard-v1/original-ast.json
python scripts/research/benchmark_combined_source_guard_timing.py --run-allocated --source-check-mode whole-file-sha --output benchmark-output/field-cuda-study/combined-sync-source-guard-v1/whole-file-sha.json
```

Proof preflight, constructor work and fresh cloud setup are excluded from the
component wall and reported separately. Cold target index construction remains
inside first registration. Source guards are charged inside each registration;
preenqueue bookkeeping includes host configuration, buffer/reset and view work.
These timers overlap enclosing measurements and support no additive or
subtractive shader-time claim. No GPU event timing is collected.

Closure requires 236 source checks and 11,569 iteration checks/preenqueue samples
per combined round, plus the inherited 104,123,989 query rows, 10,861 pose
iterations, all original gates, zero hard faults and unchanged inputs/runtime/
source bytes. All owned hooks restore before the deferred worker terminates.
Early, malformed-partial, late and cleanup faults force a failed current report.

All 26 stdlib contracts and the CLI help check from another directory passed.
The contract command imports no NumPy, Open3D, CuPy or OpenCV:

```powershell
python -S -m unittest tests.test_combined_source_guard_contract
```

Both fresh physical A/B runs subsequently closed with actual exit zero, unchanged
source/runtime/input bindings and every original proposal gate passing in all
three rounds. The complete component wall medians were:

| Source guard | Contemporary native CPU | Original Device resident | Combined sibling |
| --- | ---: | ---: | ---: |
| Original AST | 11.34128 s | 7.99940 s | 9.51528 s |
| Whole-file SHA | 11.13006 s | 7.61491 s | 7.17259 s |

The SHA sibling used 24.6% less component wall than its AST control and 5.8% less
than its contemporary Device resident control. Its CPU-to-GPU component ratio
was 1.55. Nested source-check wall fell from a median 1.6496 seconds to 0.0661
seconds; nested preenqueue bookkeeping was approximately 0.335 versus 0.349
seconds. Those nested measurements explain a concrete host overhead, without
subtracting them to assert a separate kernel or solver time.

Each mode has three rotating-order rounds, but the two complete mode runs were
executed successively. Contemporary CPU/Device controls and the fixed correctness
gates help assess variation; they do not convert a small component improvement
into a complete Finish or camera-throughput result. No production path selects
this sibling. Original field trajectory failures and all original measured
reports retain their existing scope and status.
