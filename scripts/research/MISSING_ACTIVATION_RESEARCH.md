The official [Open3D HashMap source](https://raw.githubusercontent.com/isl-org/Open3D/v0.19.0/cpp/open3d/core/hashmap/HashMap.cpp) reserves for current size plus every incoming row before determining which keys already exist. Its [API contract](https://raw.githubusercontent.com/isl-org/Open3D/v0.19.0/cpp/open3d/core/hashmap/HashMap.h) distinguishes insertion masks from find masks. These v0.19 sources explain the hypothesis; the closed physical proof independently demonstrates the behaviour on the installed v0.20 CPU/CUDA backend.

`final_missing_activation.py` pins all three original weighted CPU, tensor and fused CUDA callers. Each discards the activation tuple, then finds and integrates the **full original ordered frustum**. A private candidate proxy finds existing keys and activates only missing keys in their original order. New attributes still initialize through native activation at each original frame. The original full find, voxel coordinates, attributes, integration batches, confidence values, truncation and arithmetic remain in place. There is no union preactivation. Original unique int32 N×3 tensors on CPU:0/CUDA:0 are required; duplicates, malformed tensors, wrong devices, insufficient physical capacity and policy changes fail before native mutation. Unweighted native `VBG.integrate` is refused because it bypasses the proxy.

For supported unique inputs the returned tuple contains all post-find buffer indices and masks that are true only for previously absent keys. Existing-key index slots are explicitly resolved; the reviewed original callers discard this tuple. This scope does not authorize arbitrary code to replace HashMap activation semantics.

The Final scope uses the unchanged exact-union planner and original Final body. It returns the actual native VBG for original mesh validation/commit. Mutable Python containers and input/confidence adapter dictionaries are private and preserve their internal aliases. Original CPU calibration globals/LRU caches are privately cloned without changing function code. Existing native GPU operator owners/configuration are observed rather than deep-copied. V2 records modules and callables as owners with type/name, without invoking or traversing them. Only numeric shape sequences are interpreted as array metadata; same-name module replacement and retained array-shape changes remain detectable. Shared module contents, native array contents, pools, scratch and immutable compiled-kernel caches have no claimed bitwise rollback. Actual private preparation counters/status and failed work are reported separately; successful Final elapsed diagnostics remain recorded. Fresh prepared-input parity and mesh evidence are required before any use beyond research.

Native activation inputs and outputs remain owned until explicit selected-device synchronization, including failure. A native or synchronization fault latches, preserves the first failure and prevents retry/commit. The Final key check compares actual native active keys with the union of original requested coordinates and the planner's required count, and requires initial/final capacity to remain exact.
